# 计算机网络-第八章-互联网上的音频/视频服务

## 1. 概述

&emsp;&emsp;对于多媒体信息而言：其与以前不包含声音图像的信息的特点有：1. 信息量巨大；2. 传输多媒体数据，对时延和时延抖动有较高要求；

&emsp;&emsp;在模拟信号的多媒体信号处理的时候，分组发送的时间间隔都是恒定的，这样的分组为等时的；这种等时分组进入互联网速率恒定，但是经过互联网传送到接收端，就变成了非等时的；

![image-20250507081518547](https://azwcl-blog.oss-cn-shanghai.aliyuncs.com/picgo/2025/05/17465769184cb070.png)

&emsp;&emsp;此处处理，可以在接收端设置适当大小缓存，当分组数达到一定数量，再以恒定速率按顺序将这些分组读出并且进行还原播放；

![image-20250507081609680](https://azwcl-blog.oss-cn-shanghai.aliyuncs.com/picgo/2025/05/17465769691a7e07.png)

![image-20250507081636103](https://azwcl-blog.oss-cn-shanghai.aliyuncs.com/picgo/2025/05/174657699626091d.png)

&emsp;&emsp;这样增加了一个播放时延，但是很大程度上消除了时延的抖动；再互联网上，运输层对这种数据传送，采用 UDP，对于实时数据，宁可丢失少量分组，也不要太晚到达的分组；丢失容忍时实时数据传输的一个重要特点；

&emsp;&emsp;目前主要提供三种类型：流式存储音频/视频、流式实况音频/视频、交互式音频\视频；

## 2. 流式存储音频/视频

![image-20250507083108265](https://azwcl-blog.oss-cn-shanghai.aliyuncs.com/picgo/2025/05/1746577868b256cc.png)

&emsp;&emsp;传统浏览器，从服务器下载已存储的音频/视频文件如上图；需要等**完全收下**文件后，才可以播放；这样历时太长，下载者不愿意等待；

### 2.1. 具有元文件的万维网服务器

&emsp;&emsp;第一种：在万维网的服务器中，增加元文件，描述文件的重要信息；采用元文件下载音频/视频文件：

![image-20250507083337132](https://azwcl-blog.oss-cn-shanghai.aliyuncs.com/picgo/2025/05/1746578017f7300b.png)

1. 浏览器，点击 url 获取数据元文件，而非真是文件；
2. 服务器返回元文件，并且在响应报文指出文件类型首部；
3. 客户端得到响应，分析，调用相关媒体播放器，提出元文件传给媒体播放器；
4. 媒体播放器采用元文件 url 与服务器建立连接；并且且发送报文，下载；
5. 服务器响应；客户端存储若干秒后开始以流形式边下载，边解压，边播放；

### 2.2. 媒体服务器

&emsp;&emsp;为了更好提供服务，最流行是分开两个服务器，一个是普通万维网服务器，另一个是媒体服务器；

![image-20250508081552965](https://azwcl-blog.oss-cn-shanghai.aliyuncs.com/picgo/2025/05/1746663353a0424f.png)

### 2.3. 实时流式协议 RTSP

&emsp;&emsp;目前是 RTSP 2.0 版本，为了给流式过程增加更多功能而设计的协议；本身并不传送数据，仅仅使媒体播放器能控制多媒体流的传送，类似文件传送协议 FTP 有一个控制信道；因此 RTSP 又称为**带外协议**；

&emsp;&emsp;RTSP 协议以客户-服务器方式工作，应用层的**多媒体播放控制协议**；用来使用户在播放从互联网下载的实时数据时能够进行控制，因此又称为：**互联网录像机遥控协议**；

![image-20250508083703552](https://azwcl-blog.oss-cn-shanghai.aliyuncs.com/picgo/2025/05/1746664623bdda0d.png)

1. 浏览器采用 HTTP GET 请求音/视频文件；
2. 万维网服务器，返回元文件响应；
3. 浏览器接收到的元文件传送给媒体播放器；
4. 媒体播放器 RTSP 发送 SETUP 报文和媒体服务器的 RTSP 服务器建立连接；
5. 媒体服务器 RTSP 服务器发送响应 RESPONSE 报文；
6. 媒体播放器 RTSP 客户发送 PLAY 报文下载音/视频文件；
7. 媒体服务器 RTSP 服务器发送 RESPONSE 报文；
8. 用户不想看了，发送 TEARDOWN 断开连接报文；
9. RTSP 发送 RESPONSE 响应报文断开；
